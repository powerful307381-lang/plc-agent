# 07 导入编译闭环（Openness 生产级规范）

> 本规范融合了 Siemens TIA Portal Openness 官方最佳实践（进程生命周期安全、CPU 软件容器递归查找、`ExclusiveAccess` 事务原子回滚、二次迭代增量改动指纹预检、嵌套编译诊断树解析、交叉引用审计与全局库归档）。

## 1. 连接与会话安全（附加到用户已打开的博途）

### 1.1 动态发现与加载 Openness DLL
- **禁止全盘扫描 `Siemens.Engineering.dll`**。
- 先查询注册表 `HKEY_LOCAL_MACHINE\SOFTWARE\Siemens\Automation\_InstalledSW\TIAP16\Global` 的 `Path` 值（同时兼容 `Registry64` 与 `Registry32` 视图），拼接 `PublicAPI\V16\Siemens.Engineering.dll`；若未命中则使用本机 Junction 路径 `C:\Program Files\Siemens\Automation\Portal V16\PublicAPI\V16\Siemens.Engineering.dll`。

### 1.2 附加（Attach）与进程句柄禁令
- 调用 `TiaPortal.GetProcesses()` 获取当前运行的博途进程列表，并通过 `Select-TiaProcess` 与 `Select-PlcSoftware` 显式定位目标：
  - 0 个进程：提示用户先打开博途 V16 与目标项目并退出（`exit 1`）。
  - 1 个进程 / 1 台 PLC：自动附加并选择唯一 PLC。
  - **多个进程或多个 PLC**：**严禁静默回退到 `procs[0]` 或第一个 PLC**！未显式传入 `-ProcessIndex` / `-ProjectPath`（或索引越界）以及未传入 `-PlcName` 时，脚本将输出包含候选清单的 JSON 报错并退出（`exit 2`），等待用户明确选择。
- 🛑 **两条绝对禁令（防止杀死用户的博途进程）**：
  1. **严禁对 `TiaPortal.GetProcesses()` 返回的任何 `TiaPortalProcess` 句柄调用 `.Dispose()`**：在 Openness 中释放 `GetProcesses()` 枚举出的句柄会直接强杀正在运行的博途实例！让垃圾回收器（GC）自然回收即可。
  2. **严禁在脚本结束时调用 `project.Close()` 或 `tia.Dispose()`**：因为会话与项目由用户手动打开（所有权归属用户），脚本仅借用会话完成导入与编译。
- **后台线程公寓模型要求**：若在后台工作线程或服务中执行 `Attach()`，线程必须设为 `ApartmentState.MTA`（后台 `STA` 线程没有 Windows 消息泵，会导致 Openness .NET Remoting IPC 握手永久挂起）。

### 1.3 防火墙、许可证与包完整性异常排查
- 首次附加时博途会弹出 Openness 访问确认窗口，提醒用户点“**是 / 全部允许**”。
- 捕获并翻译关键异常：
  - `EngineeringSecurityException`：Openness 防火墙拒绝访问 → 提示用户重新运行并在博途弹窗点击“全部允许”，或检查是否在 `Siemens TIA Openness` Windows 用户组中（加入组后必须**注销并重新登录 Windows** 才生效）。
  - `LicenseNotFoundException`：缺少 STEP 7 许可证 → 提示用户打开 Automation License Manager 检查授权。
  - **空设备集合检查**：若项目引用了未安装的可选包，`Attach()` 不会抛异常，但 `project.Devices` 会为空集合——必须在阶段 0 显式检查。
- 控制台中文乱码防御：先执行 `chcp 65001`，设置 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` 及 `PYTHONIOENCODING=utf-8`。

## 2. 递归定位 CPU 与 `PlcSoftware` 容器

`SoftwareContainer` 服务挂载在代表 CPU 槽位的子 `DeviceItem` 上，**直接对 `Device` 调用 `GetService<SoftwareContainer>()` 永远返回 `null`**；同时设备可能位于设备用户组（`DeviceGroups`）或未分组设备（`UngroupedDevicesGroup`）中。必须使用完整递归查找：

```powershell
# 递归从 DeviceItem 树中获取 PlcSoftware（排除 HmiTarget 等非 PLC 软件容器）
function Get-PlcTargetFromDeviceItem($dev, $deviceItem) {
    $methods = $deviceItem.GetType().GetMethods() | Where-Object { $_.Name -eq "GetService" -and $_.IsGenericMethod }
    if ($methods) {
        try {
            $swCont = $methods[0].MakeGenericMethod(@([Siemens.Engineering.HW.Features.SoftwareContainer])).Invoke($deviceItem, $null)
            if ($swCont -and $swCont.Software -and ($null -ne $swCont.Software.PSObject.Properties["BlockGroup"])) {
                return [PSCustomObject]@{ Device = $dev; CpuItem = $deviceItem; DeviceName = $dev.Name; PlcName = $deviceItem.Name; Software = $swCont.Software }
            }
        } catch {}
    }
    foreach ($sub in $deviceItem.DeviceItems) {
        $res = Get-PlcTargetFromDeviceItem $dev $sub
        if ($res) { return $res }
    }
    return $null
}

# 枚举项目中所有位置的 Device（顶层 Devices + 递归 DeviceGroups + UngroupedDevicesGroup）
function Get-AllProjectDevices($proj) {
    $list = @()
    foreach ($d in $proj.Devices) { $list += $d }
    function Walk-DeviceGroup($grp) {
        $res = @()
        foreach ($d in $grp.Devices) { $res += $d }
        foreach ($sub in $grp.Groups) { $res += Walk-DeviceGroup $sub }
        return $res
    }
    foreach ($g in $proj.DeviceGroups) { $list += Walk-DeviceGroup $g }
    if ($proj.UngroupedDevicesGroup) {
        foreach ($d in $proj.UngroupedDevicesGroup.Devices) { $list += $d }
    }
    return $list
}
```

- **性能准则**：Openness 无内置缓存，每次 `.` 属性或 `[0]` 索引访问都是一次跨进程 IPC 调用。将 `PlcSoftware`、`BlockGroup`、`TagTableGroup` 缓存在局部变量中复用，避免在循环中重复链式导航。

## 3. 导入前准备：语义指纹预检、Gate 3 令牌、归档备份与目标断线

1. **全类型语义指纹预检（`block_fingerprint.py`，严格只读）**：
   - 现场调试可能微调了定时器参数、互锁触点、变量地址或 UDT 成员；直接覆盖会导致现场修改丢失。
   - **只读预检流程（关卡③）**：在正式导入前，必须先以 `-DiffOnly` 参数运行 `do_import_pipeline.ps1`。脚本临时导出博途内已存在的同名对象（覆盖 `UDT`、`TagTable`、`GlobalDB`、`FB`、`InstanceDB`、`FC`、`OB` 全类型，采用 `Find-BlockRecursive` / `Find-TagTableRecursive` / `Find-UdtRecursive` 跨文件夹递归检索），调用 `scripts/block_fingerprint.py` 进行双遍 Wire 解析与接口/变量语义指纹对比（忽略 UID 编号与纯排版差异）。
   - **Fail-Closed 原则**：若博途导出失败或指纹解析脚本返回错误，按 `CompareFailed = $true` 与“存在实质差异”处理并醒目标警，禁止静默放行。
   - **Gate 3 `ConfirmToken` 硬门禁**：`-DiffOnly` 模式会返回基于待导入文件集、选定范围与差异清单生成的 16 位十六进制 `ConfirmToken`。正式导入时必须向 `do_import_pipeline.ps1` 传入用户确认后的 `-ConfirmToken "<Token>"`；若缺失、不匹配或期间改动了任何 XML 文件，脚本在任何写操作之前立即报错（`Stage="Gate3"`）并退出。
   - **增量保护开关 `-SkipExistingBlocks` / `-SelectedBlocks`**：7 类对象（含 `UDT` 与 `TagTable`）均支持在 `-SkipExistingBlocks` 下保留现场存在实质差异的已有对象；或通过 `-SelectedBlocks "FC1,FC2"` 限定仅导入指定对象。
2. **强制保存与归档备份（Fail-Closed）**：
   - Gate 3 校验通过后、正式修改工程之前，必须提供非空 `-BackupDir` 参数（推荐 `<项目目录>\04_导入编译日志\备份`）；
   - 脚本依次调用 `project.Save()` 与 `project.Archive(BackupDir, "<项目名>_backup_<时间戳>.zap16", ProjectArchivationMode.Compressed)`，并校验生成的 `.zap16` 文件存在且大小大于 0；任一步骤失败（包括未传 `-BackupDir`）将立即报错（`Stage="Backup"`）并中止导入，禁止未备份直接修改工程。
3. **仅断开目标 PLC 设备在线监视（`GoOffline`）**：
   - 若目标 PLC 处于在线状态，导入会报 `This function is not supported in online mode`。通过 `Select-PlcSoftware` 锁定目标设备 `$targetDevice` 后，仅递归该设备及其子 `DeviceItem` 的 `OnlineProvider` 服务调用 `GoOffline()`，不干扰项目内其他无关设备。
4. **跨组/跨表全局冲突与导入路由规则**：
   - 博途规定：**变量名跨所有变量表全局唯一，块名/块编号跨所有块文件夹全局唯一**；预检阶段会递归搜索全树识别冲突。
   - **统一根组路由规则**（`do_import_pipeline.ps1` 导入目标）：
     - `UDT_*.xml`（`SW.Types.PlcStruct`） → `PlcSoftware.TypeGroup.Types`
     - `TagTable_*.xml`（`IO变量表`、`M辅助继电器表`） → `PlcSoftware.TagTableGroup.TagTables`
     - `DB_*`、`FB*`、`iDB_*`、`FC*`、`OB1_Main` → `PlcSoftware.BlockGroup.Blocks`（统一导入至根块组，确保不会因分组差异产生重复块或两个 `OB1`）。

## 4. `ExclusiveAccess` + `Transaction` 原子导入顺序

所有工程修改建议包裹在 `ExclusiveAccess` 与 `Transaction` 事务块中（若中途异常或 3 轮编译修复仍失败，不调用 `CommitOnDispose()` 即可自动无损回滚）：

**严格导入顺序（不可颠倒，否则报 `Unresolved type/block reference`）：**
1. **PLC 数据类型 UDT（如有）**：`UDT_*.xml`（`SW.Types.PlcStruct`） → `TypeGroup.Types.Import(FileInfo, ImportOptions.Override)`
2. **变量表**：`TagTable_*.xml`（`IO变量表`、`M辅助继电器表`） → `TagTableGroup.TagTables.Import(FileInfo, ImportOptions.Override)`
3. **全局数据块 GlobalDB**：`DB_*.xml`（如 `DB_全局定时器.xml`、`DB_全局计数器.xml`、工艺 DB） → `BlockGroup.Blocks.Import(FileInfo, ImportOptions.Override)`
4. **功能块 FB（如有）**：`FB*.xml`（`SW.Blocks.FB`） → `BlockGroup.Blocks.Import(...)`
5. **背景数据块 InstanceDB（如有）**：`iDB_*.xml`（`SW.Blocks.InstanceDB`，必须在所属 FB 之后导入） → `BlockGroup.Blocks.Import(...)`
6. **业务功能 FC**：`FC1_安全与模式.xml` → 各设备 `FC*.xml` → `FC90_报警汇总.xml` → `FC91_指示灯输出.xml`
7. **主程序块 OB1**：`OB1_Main.xml`（覆盖根组中的 `Main`）

- 🛑 **代理对象失效警告**：调用 `Import(..., ImportOptions.Override)` 覆盖已有块后，此前持有的该块 `.NET` 代理引用会失效，再次访问会抛出 `EngineeringObjectDisposedException`。如需访问导入后的块，必须重新通过 `Blocks.Find(name)` 获取。
- 每导入一个文件记录一次：成功 / 跳过 / 失败 + 原始英文报错 + 中文翻译。

## 5. 编译作用域、嵌套诊断树解析与交叉引用审计

1. **选择正确的编译作用域**：
   - 单块快速验证：`block.GetService<ICompilable>().Compile()`
   - PLC 软件全量编译（阶段 4 标准）：`plcSoftware.GetService<ICompilable>().Compile()`
2. **递归提取嵌套 `Messages`（严禁只读顶层）**：
   - Openness 的编译结果 `CompilerResult.Messages` 是树状结构，顶层消息往往只有汇总或空字符串，具体报错所在的块名、程序段号和原因位于深层子 `Messages` 中，必须递归展平：
   ```powershell
   function Extract-CompileMessages($msgNode, $parentPath = "") {
       $list = @()
       $curPath = if ($msgNode.Path) { "$($msgNode.Path)" } else { $parentPath }
       if (-not [string]::IsNullOrWhiteSpace($msgNode.Description)) {
           $list += [PSCustomObject]@{
               Severity    = "$($msgNode.Severity)"
               Path        = $curPath
               Description = "$($msgNode.Description)"
               DateTime    = "$($msgNode.DateTime)"
           }
       }
       if ($msgNode.Messages) {
           foreach ($sub in $msgNode.Messages) {
               $list += Extract-CompileMessages $sub $curPath
           }
       }
       return $list
   }
   ```
3. **自动修复闭环、事务编译策略与保存校验（1 次执行 = 1 轮，最多 3 轮）**：
   - 输出编译结果表：`| 级别 | 块/程序段路径 | 英文原文 | 中文解释 | 修复方案 |`，每次执行完整结果须落盘至 `04_导入编译日志/第N轮_导入编译.json`。
   - **事务内外编译兼容策略**：
     - 默认优先尝试**事务内编译**（`InsideTransaction`）：若编译发现错误（`ErrorCount > 0` 或导入阶段存在失败），直接放弃 `CommitOnDispose()`，由 `finally` 释放事务自动全量回滚，博途工程保持洁净；
     - 若某些博途版本/对象组合拒绝在 `Transaction` 内调用 `ICompilable.Compile()` 并抛出异常，或用户显式传入 `-CompileOutsideTransaction`：脚本自动提交导入阶段事务（`$committed = $true`）并立即 `Dispose()` 该事务，随后仍在 `ExclusiveAccess` 互斥锁定期间执行**事务外编译**。
     - **事务外编译失败安全守则**：若事务外编译仍出现错误，脚本返回 `Success = $false`、`RollbackRequired = $true` 与备份恢复指引 `RecoveryHint`，**并严禁调用 `project.Save()`**（用户可在博途中关闭不保存或使用 `.zap16` 备份回退）。
   - 当 `ErrorCount > 0` 时：定位到对应 XML 源文件 → 修正 → 重新运行 `scripts/validate_lad_xml.py` → 重新运行 `-DiffOnly` 获取最新 `ConfirmToken` → 进入下一轮导入编译（**最多 3 轮**）。
   - **仅当全部导入成功、事务提交且编译 0 错误后**：
     - 通过 `CrossReferenceService.GetCrossReferences(CrossReferenceFilter.AllObjects)` 收集各块交叉引用摘要；
     - 调用 `project.Save()` 并捕获保存异常：若 `Save()` 抛出异常，记录 `SaveError` 并置 `Saved = $false`、`Success = $false`，禁止掩盖写盘失败。
   - **警告（Warning）**不阻止交付，但每一条都要用中文说明是否影响运行。
   - **禁止**为了通过编译而删除安全逻辑、互锁或注释。

## 6. 全局库沉淀归档（`archive-to-library`）

在现场调试通过后，可将验证合格的标准设备控制 FC/FB（如星三角降压启动、双电控气缸控制）通过 `tia_bridge_core.ps1` 归档沉淀至西门子全局库（User Global Library）：
```powershell
powershell -ExecutionPolicy Bypass -File <技能目录>/scripts/tia_bridge_core.ps1 `
  -Action archive-to-library `
  -LibraryPath "D:\TIA_Libraries\EPLAN标准库" `
  -LibraryName "EPLAN_Standard_Lib" `
  -BlockNames "FC1_安全与模式,FC2_电机控制"
```
（多博途进程或多 PLC 时按 §1.2 追加 `-ProcessIndex`/`-ProjectPath` 与 `-PlcName`；底层由 Openness `UserGlobalLibrary.MasterCopyFolder.MasterCopies.Create(...)` 写入并执行 `Save()` + `Close()` 释放文件锁，严禁释放博途实例。）

## 7. 绝对不允许做的事
- 不下载程序到 PLC（下载由用户在现场脱开机械负载后手动操作）。
- 不修改硬件组态、不修改 PLC 的保护等级/密码。
- 不关闭用户的博途项目、不释放 `GetProcesses()` 进程句柄。
