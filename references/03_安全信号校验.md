# 03 安全信号校验（Fail-Safe）

## 1. 核心原理（必须向新手讲清楚）
> 常闭（NC）接线 + 程序用常开触点扫描 = “有电才算正常”。
> 一旦**按下急停、热继跳闸、碰到限位，或者线断了**，PLC 输入都会变成 0，设备停机。这叫“失效安全”：任何故障都朝安全的方向发展。

| 信号 | 现场接线 | 正常时 PLC 输入 | 梯形图触点 | 含义 |
|---|---|---|---|---|
| 急停 | NC（11-12） | 1（灯亮） | 常开 `-\| \|-` | 接通 = 允许运行 |
| 停止按钮 | NC（11-12） | 1 | 常开 `-\| \|-` | 按下变 0 → 停 |
| 热继 | NC（95-96） | 1 | 常开 `-\| \|-` | 跳闸变 0 → 停并报警 |
| 极限限位 | NC | 1 | 常开 `-\| \|-` | 碰到限位变 0 → 停该方向 |
| 启动按钮 | NO（13-14） | 0 | 常开 `-\| \|-` | 按下变 1 → 启动 |

⚠ **新手最常犯的错误**：看到“常闭按钮”，就在梯形图里画常闭触点 `-|/|-`，结果设备平时无法启动，或者断线后照样运行。**本技能禁止对 NC 安全信号使用常闭触点**（除报警检测程序段外，见第 3 节）。

## 2. 必须视为安全信号的清单
急停（`SB0` 等）、所有停止按钮、热继（`FR`）、断路器辅助触点（`QF`）、极限限位（`SQ` 保护用途）、安全门/光栅、安全继电器反馈、变频器故障（按实际触点确认）。

## 3. 程序结构要求
1. **`FC1_安全与模式`** 第一个程序段：
   `SB0_急停按钮(常开) → 串 其它全局安全条件 → 线圈 M_急停正常`
   然后 `M_急停正常 → 串 … → 线圈 M_安全条件满足`。
2. 每台设备的线圈回路中，必须串入 `M_安全条件满足`，以及该设备自己的热继（常开扫描）。
3. 报警程序段可以用常闭触点检测故障，例如 `FR1_1号电机热继(常闭) → S 置位 M_报警_1号电机热继`，在注释中写明“此处用常闭触点表示信号为 0 时报警”。
4. 急停/热继触发后，设备运行状态必须**复位**（不能恢复后自动重新启动）：需要重新按启动按钮才能运行。
5. 急停在**手动、自动两种模式下都有效**。

## 4. 自动校验规则（阶段 2、阶段 5 都要输出校验表）
| 规则 | 要求 | 校验方式 | 不通过时 |
|---|---|---|---|
| S1 | 安全信号（急停、安全门、光幕、热继）的注释必须以 `(NC)` 结尾 | 静态语法与变量表校验 | 报错，回到识图阶段确认 |
| S2 | LAD 中安全信号在使能回路只允许常开触点（`Normal`，无 `<Negated />`）读取 | `validate_lad_xml.py` 静态校验 | 报错并修正 |
| S3 | 所有输出线圈（`Coil`/`SCoil`）的电源串联前导路径都直接或间接串有 `M_安全条件满足`（且排除纯自锁绕过与并联支路伪串入） | 拓扑有向图可达性与不动点传播审计 | 报错 |
| S4 | 正反转线圈各自电源串联前导路径必须互相串入对方的常闭触点（软件互锁） | 拓扑串联前导集合审计 | 报错 |
| S5 | 电机控制线圈（含直接与间接安全依赖派生线圈）的电源串联路径串有对应热继 | 拓扑串联前导 + 传递依赖审计 | 报错 |
| S6 | 图纸缺少硬件互锁 / 急停未硬线切断 | 识图阶段与审计清单人工核对 | 不阻止生成，但在识图清单、三表首页 🔴 标红 |
| S7 | 启动按钮被误识别为 NC，或停止/急停被识别为 NO | 识图交叉校验与人工确认（Gate 1） | ⚠ 提问用户 |
